Agentic Incident Response Pipeline
Three-agent autonomous system for alert detection, root cause analysis, and remediation — with shared RAG knowledge base and internal ticket tracking.
Draft Internal Version 0.1 — June 2026 For review and feedback
What this solves

When an alert fires, multiple engineers are pulled in to triage, investigate, and fix — often spending hours on incidents that follow known patterns. This pipeline automates that entire chain, reserving human attention for genuinely novel problems.

MTTD
Faster
Alert Analyser reduces noise, surfaces real incidents faster. No human triage needed to separate genuine alerts from noise.
MTTA
Instant
RCA Agent starts investigation immediately on escalation. No human acknowledgement step for known patterns.
MTTR
Automated
Action Agent applies known fixes automatically via Jenkins. Tracked escalation to Jira when automation is not available.

Agent pipeline — step by step
Agent 1 — Alert Analyser
Detect, classify and escalate
Existing agent — extend
On each sync cycle, Alert Analyser reads new alerts from OpsGenie / JSM. It deduplicates, scores noise, and enriches genuine alerts with inventory context (account, environment, customer). It then checks the RAG store for known patterns matching this alert's signature.
  • Deduplicate — same incident fired by multiple tools counts once
  • Classify each alert as genuine, noise, or suspect using rule-based scoring
  • Enrich genuine alerts with inventory context (customer, application, environment)
  • Look up RAG for known patterns matching this alert signature
  • Create an incident ticket with enriched context and RAG hit (if any)
  • Set ticket status to ESCALATED — RCA Agent picks it up via polling
Ticket created → status: ESCALATED
Agent 2 — RCA Agent
Investigate and find root cause
New agent — to build
RCA Agent polls the incident_management DB for tickets in ESCALATED status. For each ticket it picks up, it updates the status to INVESTIGATING, then begins autonomous analysis using the enriched alert context, RAG findings, and available data sources (logs, metrics, deployment history, service dependencies).
  • Poll DB for ESCALATED tickets — update to INVESTIGATING on pickup
  • Query RAG for previous occurrences of the same alert signature
  • Investigate logs, metrics, and service dependencies autonomously
  • Correlate with recent deployments, config changes, or dependency failures
  • Produce structured finding: root cause, evidence, confidence score
  • Recommend specific remediation actions (Jenkins job, config change, rollback)
  • Write findings back to RAG — future incidents with same pattern benefit immediately
  • Update ticket with findings and set status to RCA_COMPLETE
Ticket updated → status: RCA_COMPLETE + findings attached
Agent 3 — Action Agent
Remediate and record outcome
New agent — to build
Action Agent polls for tickets in RCA_COMPLETE status. It reads the RCA findings and recommended actions, then checks whether a Jenkins job exists for the recommended fix. If yes, it triggers the job and monitors execution. If no, it creates a Jira ticket with full RCA context for the on-call engineer.
  • Poll DB for RCA_COMPLETE tickets — update to REMEDIATING on pickup
  • Check Jenkins job catalogue for a job mapped to the recommended action
  • If job exists — trigger, monitor execution, verify resolution in OpsGenie
  • If no job — create Jira ticket with full RCA context for on-call engineer
  • Record outcome (success / failure / manual escalation) back to ticket
  • Feed outcome to RAG — successful fixes become known-good actions for future
  • Feed results back to Alert Analyser for enriched escalation context in future
  • Set ticket to RESOLVED (automated) or MANUAL (human intervention needed)
Ticket updated → status: RESOLVED or MANUAL
Shared RAG — Continuous improvement
Knowledge base grows with every incident
New shared service — to build
All three agents read from and write to a shared RAG store. Over time, the system learns which alert signatures map to which root causes, which Jenkins jobs resolve which issues, and which patterns repeat. Each incident makes the next one faster to resolve.
  • Alert patterns and signatures — dedup and noise detection improves over time
  • Root cause findings — matched by alert signature for instant RCA on repeat incidents
  • Recommended actions and their outcomes — Action Agent knows which fixes work
  • Jenkins job mappings — auto-populated as successful remediations are recorded
  • Jira tickets created — tracked alongside automated resolutions for audit

Deployment model
Alert Analyser
Existing agent — extended
Add ticket writer. Add RAG client. Existing dedup, classify, enrich logic unchanged.
RCA Agent
New standalone agent
Polls incidents DB. Reads logs/metrics. Writes findings. Feeds RAG. Standalone FastAPI.
Action Agent
New standalone agent
Polls incidents DB. Jenkins integration. Jira escalation. Feeds outcome to RAG.
Shared Postgres
incident_management DB — existing instance
Separate logical DB in operative_db Postgres. Schema owned by Alert Analyser (created on startup). All agents read/write.
Incident Dashboard
Standalone — independently deployable
Lightweight FastAPI (read-only) + nginx + HTML/JS. Deployable on UAP or any platform that can reach Postgres. Shows live pipeline, MTTD/MTTA/MTTR, audit trail.
