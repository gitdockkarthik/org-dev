📊 Kafka Analyser

Kafka cluster health monitoring, consumer lag detection, broker metrics and anomaly intelligence agent

v1.1.0 Internal FastAPI + PostgreSQL Updated 2026-07-16 Port 8003

Real-time Monitoring

Consumer lag, broker metrics (CPU, heap, GC), topic throughput (msg/sec), partition counts, and replica sync status.

6 Data Sources

Synthetic, Real Kafka (bootstrap), Prometheus JMX, Schema Registry, ZooKeeper, KafkaConnect, MirrorMaker replication tracking.

5 AI Tools

cluster_overview, consumer_lag, broker_metrics, topic_metrics, detect_anomalies with Claude tool-use loop.

Technical Architecture

Stack

  • Compute: FastAPI (Python 3.11) on Operative platform (port 8003)
  • Storage: PostgreSQL (cluster config, metrics history, anomalies, connectors)
  • In-memory: kafka_store (current cluster snapshot, consumer groups, topics, brokers)
  • Data Sources: Real Kafka, Synthetic generator, Prometheus JMX, Schema Registry, ZooKeeper, KafkaConnect, MirrorMaker
  • Optional backends: Redis (cache), Vector DB (embeddings), Neo4j (graph topology) — configured via env

Dashboard Features

📌 Overview

Cluster health score, broker status summary, URP count, active anomalies, consumer lag trend chart.

👥 Consumer Groups

All groups sorted by lag (worst-first), lag trend (growing/stable/recovering), messages/min, group state.

📝 Topics

Topic throughput (msg/sec, bytes in/out), retention usage %, partition count, replication factor, history.

🖥️ Brokers

Per-broker CPU%, heap%, GC pause ms, request handler idle%, URP count, disk%, metrics trend.

🔗 KafkaConnect

Connector status (running/failed/paused), failed task count, connector type (source/sink), state history.

🗃️ Schema Registry

Schema versions, compatibility levels per subject, schema evolution tracking, subject listing.

🌳 ZooKeeper

ZooKeeper node health, leader election status, broker registration state, config changes.

↔️ MirrorMaker

Cross-cluster replication lag, checkpoint offsets, mirror mode (active/passive), replication rate.

🤖 AI Insights

Anomaly detection (critical/warning severity), remediation steps, chat Q&A with tool-use, pattern learning.

Key Business Outcomes

  • Reduces MTTR: Consumer lag trends surfaced before SLA breach; anomaly alerts on GC spikes, URP growth.
  • Unified interface: 6 data sources (Kafka, Prometheus, Schema Registry, ZK, KafkaConnect, MirrorMaker) in one place — no tool-switching.
  • Early detection: Broker degradation (high GC%, URP, heap) caught in real-time; historical trends enable trend-based alerting.
  • PostgreSQL history: Long-term metrics enable root-cause analysis beyond real-time dashboards.
  • 7-source support: Synthetic, Real Kafka, Prometheus JMX, Schema Registry, ZooKeeper, KafkaConnect, MirrorMaker — flexible deployment.
  • AI chat: 5 tool-use functions enable operators to ask natural-language questions about cluster health without leaving the chat.
