📚 Kafka Analyser API Reference

REST API endpoints for Kafka cluster monitoring, analysis and configuration

v1.1.0 Port 8003 FastAPI Base URL: http://<host>:8003

Authentication

All endpoints require: X-API-Key: <BACKEND_API_KEY> header

The backend orchestrator injects the Anthropic API key per-request; agents never store secrets.

Health & Chat

GET /health
Agent health check. Used by backend registry to verify agent is running.
Response
{ "status": "ok", "agent": "kafka-analyser", "version": "0.1.0" }
Example
curl -X GET http://localhost:8003/health
POST /invoke
Chat invoke (non-streaming). Runs Claude tool-use loop for question answering.
Request Body
session_id (string) — Chat session ID for history tracking
user_message (string) — User question or command
context (object) — Query context (optional)
  • cluster_id — ID of target cluster (optional)
  • has_data — Boolean flag if cluster has loaded data
Response
response — Claude's text response
metadata.tokens_used — Token count for billing
chart (object, optional) — Chart data if response includes visualization
Example
curl -X POST http://localhost:8003/invoke \ -H "X-API-Key: your-api-key" \ -H "Content-Type: application/json" \ -d '{ "session_id": "abc123", "user_message": "What is the consumer lag trend?", "context": {"cluster_id": 1, "has_data": true} }'
POST /invoke/stream
Streaming chat invoke. Response is SSE (Server-Sent Events) stream of text chunks.
Request Body
Same as /invoke
Response
SSE stream of chunks ending with [DONE]

Dashboard Overview

GET /dashboard/overview
Cluster health overview with broker counts, topic metrics, and anomaly summary.
Query Parameters
cluster_id (integer, optional) — Cluster to query (uses first if not provided)
Response
cluster — Cluster metadata (name, health_score, broker/topic/partition counts, URP count)
brokers — Array of broker summaries
anomaly_count — Total active anomalies
critical_count — Critical severity anomalies
warning_count — Warning severity anomalies
GET /dashboard/counts
Alert and anomaly counts summary for quick KPI rendering.
Response
total_brokers — Total brokers in cluster
active_brokers — Currently healthy brokers
total_topics — Topic count
total_consumer_groups — Consumer group count
active_anomalies — Unresolved anomalies
critical_anomalies — Critical severity count

Dashboard Metrics

GET /dashboard/brokers
Per-broker metrics sorted by broker ID.
Query Parameters
cluster_id (integer) — Cluster to query
Response
Array of broker objects with: broker_id, cpu_pct, heap_pct, gc_pause_ms, request_handler_idle_pct, urp_count, messages_in_per_sec, disk_pct
GET /dashboard/consumer-groups
Consumer group lag analysis sorted worst-first.
Query Parameters
cluster_id (integer) — Cluster to query
Response
Array of groups with: group_name, total_lag, lag_trend (growing|stable|recovering), lag_rate_per_min, state, topics subscribed
GET /dashboard/topics
Topic metrics sorted by message rate (throughput worst-first).
Query Parameters
cluster_id (integer) — Cluster to query
Response
Array of topics with: topic name, partition/replication counts, messages_in_per_sec, bytes in/out per sec, retention_pct, size_bytes
GET /dashboard/topics/detail
Detailed topic view with historical metrics.
Query Parameters
cluster_id (integer) — Cluster ID
topic (string) — Topic name
Response
topic — Topic name
metrics — Current metrics snapshot
history — Time-series history (last 24 hours)

Settings & Configuration

GET /settings
Get current cluster configuration.
Response
clusters — Array of configured clusters with id, name, environment, source_type, bootstrap_servers, enabled, status
POST /settings/clusters
Add or update a Kafka cluster connection.
Request Body
name (string) — Display name
environment (string) — prod, staging, dev
source_type (string) — synthetic, real, prometheus
bootstrap_servers (string) — Kafka bootstrap address(es)
auth_type (string) — none, sasl, tls
sasl_username (string, optional) — SASL credentials
sasl_password (string, optional) — SASL credentials (encrypted)
tls_enabled (boolean) — TLS encryption
schema_registry_url (string, optional) — Schema Registry endpoint
zookeeper_url (string, optional) — ZooKeeper endpoint
kafka_connect_url (string, optional) — KafkaConnect endpoint
Response
ok — Boolean success
cluster_id — ID of created/updated cluster
DELETE /settings/clusters/{cluster_id}
Remove a cluster connection.
Response
ok — Boolean success
deleted — Cluster ID that was removed
POST /settings/clusters/{cluster_id}/test
Test cluster connectivity and collect basic info.
Response
ok — Boolean success (connection works)
latency_ms — Round-trip time to broker
broker_count — Number of brokers discovered
kafka_version — Kafka broker version
POST /settings/generate-synthetic
Generate synthetic cluster data for demo and testing.
Request Body
broker_count (integer, default 3) — Number of brokers
topic_count (integer, default 10) — Number of topics
consumer_groups (integer, default 5) — Consumer groups to create
Response
ok — Boolean success
cluster_id — ID of synthetic cluster
brokers — Count created
topics — Count created
consumer_groups — Count created

Job Management

APIs for managing background jobs, scheduling, and monitoring runs. Jobs are async operations like metric collection, anomaly detection, and reconciliation.

GET /jobs
List all registered jobs with schedule info.
Response
jobs — Array of job objects
job_id — Unique job identifier
name — Human-readable job name
job_type — Type: metrics, anomalies, reconciliation
status — Current status: enabled, disabled, paused
schedules — Array of active schedules (cron expressions)
GET /jobs/{job_id}/runs
Get run history for a job.
Query Parameters
limit (integer, default 50) — Max runs to return
offset (integer, default 0) — Pagination offset
Response
runs — Array of run records
run_id — Unique run identifier
started_at — Start timestamp
completed_at — Completion timestamp (null if running)
status — success, failed, timeout, running
duration_ms — Execution time in milliseconds
error — Error message if status is failed
GET /jobs/{job_id}/schedules
Get all schedules for a job.
Response
schedules — Array of schedule objects
schedule_id — Unique schedule identifier
cron_expression — Cron schedule (e.g., "0 */5 * * *")
timeout_secs — Job timeout in seconds
enabled — Boolean schedule status
next_run — Next scheduled execution timestamp
POST /jobs/{job_id}/trigger
Manually trigger a job run (ignores schedule).
Response
ok — Boolean success
run_id — ID of triggered run
status — Run status (usually running)
POST /jobs/{job_id}/schedules
Create a new schedule for a job.
Request Body
cron_expression (string, required) — Cron schedule (e.g., "0 */5 * * *")
timeout_secs (integer, default 300) — Job timeout
Response
ok — Boolean success
schedule_id — ID of created schedule
next_run — Next scheduled execution timestamp
PUT /jobs/{job_id}/schedules/{schedule_id}
Update a schedule (cron expression and/or timeout).
Request Body
cron_expression (string, optional) — New cron schedule
timeout_secs (integer, optional) — New timeout
Response
ok — Boolean success
schedule_id — Updated schedule ID
next_run — Recalculated next execution time
DELETE /jobs/{job_id}/schedules/{schedule_id}
Delete a schedule.
Response
ok — Boolean success
deleted — Schedule ID that was removed
GET /runs
List all runs across all jobs with filtering and pagination.
Query Parameters
limit (integer, default 50) — Max runs to return
offset (integer, default 0) — Pagination offset
status (string, optional) — Filter by: success, failed, timeout, running
job_type (string, optional) — Filter by job type
Response
runs — Array of run records (see /jobs/{job_id}/runs)
total — Total count of runs matching filter

SLI/SLO Management

Service Level Indicator and Service Level Objective tracking for Kafka clusters. Define targets, view compliance, and monitor trends.

GET /slo/targets
Get SLO targets for a cluster.
Query Parameters
cluster_id (integer, required) — Cluster to query
Response
cluster_id — Cluster identifier
connector_availability_target — Target % (e.g., 99.5)
consumer_lag_target — Max acceptable lag in messages
broker_availability_target — Target % for broker uptime
urp_target — Max acceptable URP count
max_broker_cpu_pct — CPU threshold %
max_broker_heap_pct — Heap threshold %
min_task_health_pct — Min healthy task % for KafkaConnect
max_failed_tasks — Max failed tasks allowed
POST /slo/targets
Save or update SLO targets for a cluster.
Query Parameters
cluster_id (integer, required) — Cluster to update
Request Body
connector_availability_target (float, optional) — Availability target %
consumer_lag_target (integer, optional) — Max lag messages
broker_availability_target (float, optional) — Broker uptime %
urp_target (integer, optional) — Max URP
max_broker_cpu_pct (float, optional) — CPU %
max_broker_heap_pct (float, optional) — Heap %
min_task_health_pct (float, optional) — Task health %
max_failed_tasks (integer, optional) — Max failed
Response
ok — Boolean success
cluster_id — Updated cluster
GET /slo/dashboard
Get full SLO dashboard data with current state, trends, and connector health.
Query Parameters
cluster_id (integer, required) — Cluster to query
hours (integer, default 24) — Hours of trend data
Response
current_state — Current SLO compliance metrics
targets — SLO targets for comparison
trend — Metric trends over requested period
connectors — Connector availability snapshot
compliance_score — Overall % compliance (0-100)
GET /slo/monthly
Get monthly SLO compliance summary.
Query Parameters
cluster_id (integer, required) — Cluster to query
months (integer, default 1) — Number of months to return
Response
months — Array of monthly summaries
month — YYYY-MM format
compliance_score — Overall compliance %
breaches — Count of SLO breaches
breach_details — List of which targets were breached
GET /slo/connector-trend
Get connector availability trend from snapshots.
Query Parameters
cluster_id (integer, required) — Cluster to query
hours (integer, default 24) — Hours of trend data
Response
connector_trends — Array of connector snapshots
timestamp — Snapshot time
healthy_count — Number of healthy connectors
failed_count — Number of failed connectors
availability_pct — Availability percentage

Dashboard Enhancements

Advanced dashboard endpoints for detailed metrics, topic inspection, and trend analysis.

GET /dashboard/counts
Get cluster counts with health indicators: topics, consumer groups, brokers, with URP, stale topics, and large topic flagging.
Query Parameters
cluster_id (integer, required) — Cluster to query
Response
topic_count — Total topics
consumer_group_count — Total consumer groups
broker_count — Total brokers
urp_count — Under-replicated partitions
stale_topics — Topics with no recent messages
large_topics — Topics exceeding size threshold
GET /dashboard/topics/detail
Get detailed information for a single topic from PostgreSQL storage.
Query Parameters
name (string, required) — Topic name
cluster_id (integer, required) — Cluster containing topic
Response
name — Topic name
partition_count — Number of partitions
replication_factor — Replication level
size_bytes — Total topic size
retention_ms — Retention period in ms
messages_in_per_sec — Ingestion rate
bytes_in_per_sec — Bytes ingestion rate
consumer_groups — Groups consuming this topic
urp — Under-replicated partitions
GET /dashboard/overview/lag-trend
Get consumer lag trend over time for historical analysis and anomaly detection.
Query Parameters
cluster_id (integer, required) — Cluster to query
minutes (integer, default 60) — Minutes of trend data
Response
datapoints — Array of lag measurements
timestamp — Measurement time
total_lag — Sum of all consumer group lags
max_lag — Highest lag in any group
group_count — Number of active consumer groups
trend — "growing", "stable", or "recovering"

HTTP Status Codes

  • 200 OK — Request succeeded
  • 202 Accepted — Async operation accepted (future enhancement)
  • 400 Bad Request — Invalid parameters or malformed request
  • 401 Unauthorized — Missing or invalid X-API-Key header
  • 404 Not Found — Resource not found (cluster, topic, group)
  • 500 Internal Server Error — Server error or Kafka connectivity issue
