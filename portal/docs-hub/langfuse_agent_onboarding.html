🚀 Agent Langfuse Onboarding

Step-by-step guide for teams building new agents — mandatory Langfuse tracing integration

Mandatory All Agents Zero-Failure Design 5 min setup

Universal Tracing

Every LLM call across all agents traces automatically to Langfuse — no custom code per agent required when using shared/llm.py.

Complete Visibility

Model, input/output tokens, cost, latency, user email, session ID, and tool execution times captured for every call.

Zero-Failure Design

Tracing is optional — agent never fails if Langfuse is unavailable. Platform observability is a guarantee, not a liability.

Overview

Why Every Agent Must Integrate Langfuse

Langfuse tracing is mandatory for all agents in the Operative Intelligence platform because it enables:

  • Cost attribution: Track LLM spend per agent, per user, per model
  • Performance monitoring: Identify latency bottlenecks, model response time regressions
  • Debugging: Full trace of every LLM interaction with token counts and error details
  • Compliance: Audit trail of all LLM invocations for legal, regulatory, or internal review
  • Portal integration: Portal admin users see cost and performance data in the Audit tab automatically

What Gets Captured

When your agent calls Claude via shared/llm.py, the following is automatically logged to Langfuse:

  • Model: e.g., claude-sonnet-4-6
  • Input tokens: Tokens sent to the model
  • Output tokens: Tokens returned by the model
  • Cost: Calculated from model pricing + token count
  • User: Email from portal auth context
  • Session ID: Groups related LLM calls in the same chat session
  • Tool calls: Name, input, execution time if agent uses tools
  • Errors: Full exception trace if call fails

Zero-Failure Design

Critical: Tracing must never cause your agent to fail. The shared/llm.py module wraps Langfuse calls in try-except blocks, so your agent works even if Langfuse is down, network is broken, or credentials are missing. This is non-negotiable.

Prerequisites

What You Need

  • Agent repository (clone of agent-template/ or existing agent)
  • Docker Compose environment (org-dev repo with backend running)
  • Basic understanding of agent.py and invoke endpoints

Environment Setup

Three environment variables must be set in your agent's docker-compose.yml block:

  • LANGFUSE_PUBLIC_KEY — shared public API key (ask platform team)
  • LANGFUSE_SECRET_KEY — shared secret API key (ask platform team)
  • LANGFUSE_HOST — Langfuse endpoint, e.g., http://langfuse:3000 (internal) or production URL

Python Package

Add to your requirements.txt:

langfuse>=2.0.0

Step-by-Step Integration

Step 1 — Add langfuse to requirements.txt

langfuse>=2.0.0

This is the SDK that shared/llm.py uses internally to send traces.

Step 2 — Set Langfuse env vars in docker-compose

  your-agent:
    image: your-agent:latest
    environment:
      - LANGFUSE_PUBLIC_KEY=${LANGFUSE_PUBLIC_KEY}
      - LANGFUSE_SECRET_KEY=${LANGFUSE_SECRET_KEY}
      - LANGFUSE_HOST=http://langfuse:3000
      - AGENT_SLUG=your-agent
      # ... other env vars

Note: LANGFUSE_HOST points to the internal Langfuse service, not the portal proxy. Agent-to-Langfuse communication is direct.

Step 3 — Use shared/llm.py for ALL LLM calls

Never import the Anthropic SDK directly. Always use:

from shared.llm import create_message, stream_message

These functions:

  • Initialize Claude via the Anthropic SDK (with API key injected by backend)
  • Automatically send traces to Langfuse
  • Handle failures gracefully (tracing never breaks your agent)

Example (non-streaming):

from shared.llm import create_message

response = create_message(
    model="claude-sonnet-4-6",
    system_prompt="You are a helpful assistant",
    user_message="What is the weather?",
    session_id=context.get("session_id")
)
print(response.content)

Step 4 — Pass session_id from context

In your agent.py AgentRunner, whenever you call create_message or stream_message, pass session_id from the invoke context:

def run(self, context: dict):
    session_id = context.get("session_id")
    response = create_message(
        model=self.model,
        system_prompt=self.system_prompt,
        user_message=context.get("user_message"),
        session_id=session_id
    )
    return response

The session_id groups all LLM calls in the same chat session, so portal users can see the full conversation trace.

Step 5 — Pass session_id in streaming invoke endpoint

If your agent has a streaming POST /invoke/stream endpoint, pass session_id from the request body:

@app.post("/invoke/stream")
async def invoke_stream(body: InvokeRequest):
    context = {
        "session_id": body.session_id,
        "user_message": body.user_message,
        # ... other context
    }
    async for chunk in stream_message(
        model=agent.model,
        system_prompt=agent.system_prompt,
        user_message=body.user_message,
        session_id=body.session_id
    ):
        yield chunk

Step 6 — Validate tracing with a test call

Make a curl request to your agent to verify tracing is working:

curl -X POST http://localhost:8001/invoke \
  -H "Content-Type: application/json" \
  -H "X-API-Key: $(grep BACKEND_API_KEY .env | cut -d= -f2)" \
  -d '{
    "session_id": "test-123",
    "user_message": "Say hello",
    "context": {}
  }'

Then navigate to Portal → Audit → LLM Usage. Your agent's trace should appear within 5 seconds.

Governance Checklist

All items below are mandatory before your agent is released to production. Use this checklist to verify compliance:

  • langfuse>=2.0.0 in requirements.txt
  • LANGFUSE_PUBLIC_KEY env var set in docker-compose.yml
  • LANGFUSE_SECRET_KEY env var set in docker-compose.yml
  • LANGFUSE_HOST=http://langfuse:3000 in docker-compose.yml
  • AGENT_SLUG env var set (e.g., my-agent)
  • All LLM calls use shared/llm.py (no direct Anthropic SDK imports)
  • session_id passed to create_message()
  • session_id passed to stream_message() in streaming endpoints
  • Test curl call succeeds and trace appears in Portal Audit tab
  • Error handling verified: agent works even if Langfuse is down

Viewing Traces

In the Portal

Once tracing is working, traces are visible to all portal users in two places:

  1. Audit → LLM Usage tab: Click this tab to see all LLM calls across all agents
  2. Filter by Agent: Use the "All Agents" dropdown to filter to your agent only
  3. Cost per Call: The "Cost (USD)" column shows the calculated cost for each call
  4. Session Grouping: Calls with the same session_id are grouped in the same chat session

Debugging Traces

If your traces aren't appearing:

  • Check logs: Run docker compose logs your-agent | grep langfuse to see if tracing errors are being silently caught
  • Verify env vars: Ensure LANGFUSE_PUBLIC_KEY, LANGFUSE_SECRET_KEY, LANGFUSE_HOST are set
  • Check langfuse container: docker compose logs langfuse to see if the Langfuse service is running
  • Network connectivity: Agent must be able to reach http://langfuse:3000 (internal Docker network)
  • Model name: Ensure the model name passed to create_message() matches the model list Langfuse expects

Common Issues

  • "ModuleNotFoundError: No module named 'langfuse'" — Add langfuse to requirements.txt and rebuild agent container
  • Traces not appearing in Portal: Verify session_id is being passed and is non-empty
  • Cost is $0 for all calls: Verify model name is correct (e.g., claude-sonnet-4-6, not claude-sonnet or claude-sonnet-4)
  • Agent hangs during trace: Should not happen with zero-failure design; check logs for exceptions and report to platform team

Shared/llm.py API Reference

create_message()

def create_message(
    model: str,
    system_prompt: str,
    user_message: str,
    session_id: str = None,
    tools: list = None,
    max_tokens: int = 4096
) -> ContentBlock:

Returns: First content block from Claude response (usually TextBlock with .text attribute)

Parameters:

  • model — e.g., "claude-sonnet-4-6"
  • system_prompt — System instructions for Claude
  • user_message — User query
  • session_id — Optional; groups calls in same session for Portal UI
  • tools — Optional; list of tool definitions for tool-use
  • max_tokens — Max tokens in response (default 4096)

stream_message()

async def stream_message(
    model: str,
    system_prompt: str,
    user_message: str,
    session_id: str = None,
    tools: list = None
) -> AsyncGenerator[str]:

Yields: Streamed text chunks as they arrive from Claude

Usage: Use in async for chunk in stream_message(...) to iterate over chunks

FAQ

Q: What if Langfuse is down?

A: Your agent continues to work. Traces are dropped, but Claude calls succeed. This is guaranteed by zero-failure design in shared/llm.py.

Q: Can I use the Anthropic SDK directly?

A: No. You must use shared/llm.py for all LLM calls. This ensures consistent tracing, API key injection, and error handling across all agents.

Q: What if I don't pass session_id?

A: Tracing still works. Traces are logged but not grouped with other calls in the same session. Portal users won't see the conversation context. Pass session_id when available.

Q: How long does tracing take?

A: Langfuse tracing is async and non-blocking. Claude call latency is unaffected. Traces may take 2-5 seconds to appear in the Portal.

Q: Can I see raw traces in Langfuse directly?

A: Yes. Portal Audit → LLM Usage tab is powered by Langfuse. Portal users only see cost and token counts, but admin users can access the full Langfuse dashboard if needed.

Q: Can I configure tracing per-agent?

A: Tracing is mandatory and always on. No per-agent config. The platform assumes all agents are tracing.
