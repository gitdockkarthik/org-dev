📡 Langfuse Deployment

Complete deployment and infrastructure guide for Langfuse observability stack within Operative Intelligence

v3.0 Internal Docker Compose Port 3001

Full Observability Stack

Langfuse v3 + ClickHouse + Redis + MinIO + langfuse-worker for complete LLM tracing, cost tracking, and performance monitoring.

No External Dependencies

All components self-contained in Docker Compose; no reliance on Langfuse Cloud. Runs on KPI box or production infrastructure.

Role-Based Access

Portal auth controls Langfuse access. Admin credentials synced with portal. Signup disabled for security.

Overview

What is Langfuse?

Langfuse is an open-source LLM observability and analytics platform that tracks every interaction with Claude across all agents. It provides:

  • Tracing: Full request/response history with token counts, latency, and cost attribution
  • Cost analytics: Input/output token pricing per model, per agent, per user, with cost attribution
  • Performance metrics: Latency, error rates, tool execution times
  • Session management: Grouped interactions for context and debugging

Architecture

The deployment consists of five core components orchestrated via Docker Compose.

Role in Operative Intelligence

Langfuse is the central observability hub for the platform, enabling cost tracking, debugging, performance monitoring, audit trails, and Audit tab integration.

Prerequisites

Environment & Ports

  • Docker Compose 2.0+, Docker Engine 20.10+
  • 8 GB RAM minimum (16 GB recommended), 20 GB free disk
  • Port 3001 (internal): Langfuse web UI proxied via portal nginx
  • Port 3000 (internal): Langfuse API for agent SDKs

Infrastructure Components

ClickHouse (Time-Series Database)

Purpose: Stores all traces, events, metrics in analytics-optimized schema.

Image: clickhouse/clickhouse-server:latest

Key Config: Database langfuse, volume ./data/clickhouse, 4GB memory pool

Resources: 2 cores, 4 GB RAM, 10+ GB disk

Redis (Session Cache & Queue)

Purpose: Caches sessions, queues langfuse-worker jobs, stores real-time metrics.

Image: redis:7-alpine

Key Config: No auth (internal only), allkeys-lru eviction, 1 GB max memory

Resources: 1 core, 1 GB RAM, minimal disk

MinIO (Object Storage)

Purpose: Stores trace exports, uploads, backups in S3-compatible format.

Image: minio/minio:latest

Key Config: Bucket langfuse-traces, volume ./data/minio, root user minioadmin

Resources: 1 core, 512 MB RAM, 5+ GB disk

langfuse-worker (Background Job Processor)

Purpose: Processes async jobs: roll-ups, aggregation, cost calculations, exports.

Image: ghcr.io/langfuse/langfuse:latest with worker entrypoint

Key Config: Entrypoint node --max-old-space-size=2048 /app/dist/server-worker.js

Resources: 1 core per worker, 512 MB-1 GB RAM, minimal disk

Langfuse v3 (API & Web UI)

Purpose: Main server: trace ingestion, API, dashboard, authentication.

Image: ghcr.io/langfuse/langfuse:latest

Key Config: Health check GET /api/health, ~30 sec startup (migrations)

Resources: 2 cores, 2 GB RAM, minimal disk (stateless)

Docker Compose Configuration

Add to docker-compose.yml. Services depend on postgres, redis, minio. Health checks ensure startup order.

langfuse:
  image: ghcr.io/langfuse/langfuse:latest
  environment:
    - LANGFUSE_DATABASE_URL=postgresql://langfuse:${LANGFUSE_DB_PASSWORD}@postgres:5432/langfuse
    - LANGFUSE_REDIS_URL=redis://redis:6379
    - LANGFUSE_S3_ENDPOINT=http://minio:9000
    - LANGFUSE_S3_ACCESS_KEY=${LANGFUSE_S3_ACCESS_KEY}
    - LANGFUSE_S3_SECRET_KEY=${LANGFUSE_S3_SECRET_KEY}
    - LANGFUSE_PUBLIC_KEY=${LANGFUSE_PUBLIC_KEY}
    - LANGFUSE_SECRET_KEY=${LANGFUSE_SECRET_KEY}
    - LANGFUSE_AUTH_DISABLE_SIGNUP=true
    - LANGFUSE_ADMIN_EMAIL=${ADMIN_EMAIL}
    - LANGFUSE_ADMIN_PASSWORD=${ADMIN_PASSWORD}
  ports:
    - "3000:3000"

langfuse-worker:
  image: ghcr.io/langfuse/langfuse:latest
  entrypoint: node --max-old-space-size=2048 /app/dist/server-worker.js
  environment: [same as langfuse above]

nginx Proxy Configuration

Portal nginx Setup

Add to portal/nginx.conf:

location /langfuse/ {
  proxy_pass http://langfuse:3000/;
  proxy_set_header Host $host;
  proxy_set_header X-Real-IP $remote_addr;
  proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
  proxy_set_header X-Frame-Options "";
}

Authentication & Integration

  • /langfuse/api/auth/session checks portal operative_token JWT cookie
  • /langfuse/api/auth/signin uses portal admin credentials
  • AUTH_DISABLE_SIGNUP=true prevents self-registration
  • Portal Audit → LLM Usage tab embeds Langfuse dashboard as iframe

Security

Access Control & Data Protection

  • Access: Portal auth gate required; no direct external access
  • Credentials: Signup disabled. Admin email/password synced with portal.
  • Secrets: LANGFUSE_SECRET_KEY, S3 keys stored in .env (gitignored)
  • Network: All components on Docker internal network (no public exposure)
  • Encryption: Internal communication via Docker network, VPN required for portal access
  • Audit: All traces logged with timestamp, model, user email, tokens in ClickHouse
